# Week 07 · 评测与作品打磨（20 小时）

当前可运行的离线评测：

```powershell
python -m projects.doc_qa.eval
python -m projects.issue_triage.eval
python -m pytest -q
```

这些命令只验证当前代码和小型虚构数据。它们不能说明真实模型的答案质量，也不能说明真实用户场景的效果。

| 时间 | 任务 |
| ---: | --- |
| 6h | 各项目补至少 20 条有代表性的样例，区分常见、边界和无答案输入 |
| 4h | 抽样人工判定：检索是否命中、答案是否被证据支持、分类是否正确 |
| 4h | 记录每个失败案例的原因、改动与复测结果；避免只展示平均分 |
| 3h | 检查安装说明、示例命令、截图、错误提示和隐私数据处理 |
| 3h | 继续投递并收集面试问题，修订项目讲解 |

## 评测记录模板

| 版本 | 数据集规模 | 指标 | 结果 | 主要失败 | 下一步 |
| --- | ---: | --- | ---: | --- | --- |
| baseline | 待填写 | 检索 Hit@3 | 待填写 | 待填写 | 待填写 |
| 改进版 | 待填写 | 检索 Hit@3 | 待填写 | 待填写 | 待填写 |

不要把同一批用于调参的样例同时当作独立测试集。保留一部分未参与改动的案例，才能判断改动是否真正泛化。
