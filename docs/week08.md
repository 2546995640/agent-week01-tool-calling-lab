# Week 08 · 简历、面试与持续投递（20 小时）

第 4 周已开始投递；本周集中打磨展示材料并根据反馈调整岗位方向。

可复制 [`application-tracker.csv`](application-tracker.csv) 记录投递。不要把含个人联系方式、内推人信息或面试反馈的实际记录提交到公开仓库。

| 时间 | 任务 |
| ---: | --- |
| 5h | 两个项目各录制 2–3 分钟演示：问题、流程、结果、失败处理 |
| 4h | 用实际测得的指标写项目经历；把仓库链接放到简历 |
| 4h | 准备下方高频追问，练习不看稿讲解 |

| 2h | 根据反馈决定下一个深挖方向：检索、工作流或工程化 |

## 项目经历模板

**文档问答：**独立实现 Markdown 文档切分、检索、来源引用与无依据拒答；构建 `N` 条人工标注样例，检索 Hit@3 从 `A%` 提升到 `B%`；通过失败案例改进 `X`。只填入真实测得的数据。

**Issue 分诊：**实现 Issue 读取、手册检索、结构化分类和回复草稿流程；将发布动作放在人工批准边界之后；构建 `N` 条标注样例，记录分类准确率和主要错误类型。当前仓库只模拟发布，简历中应明确说明。

## 面试自测

1. 模型请求工具与程序执行工具之间的边界在哪里？
2. 为什么即使声明了 JSON Schema，程序仍要校验参数？
3. `previous_response_id` 续接失败时，你如何恢复会话？
4. 检索 Hit@3 高，为什么最终答案仍可能不可靠？
5. 为什么无依据问题需要拒答？阈值怎么定？
6. 工具执行成功但模型回复前超时，重试会发生什么？
7. 人工批准在本地原型与线上服务中的实现差异是什么？
8. 你的评测集从哪里来，有哪些偏差？

对每题准备“项目中的具体代码位置 + 一个失败案例 + 你会怎样改进”。
