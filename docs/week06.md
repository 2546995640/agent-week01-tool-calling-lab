# Week 06 · 人工批准、日志与可靠性（20 小时）

| 时间 | 学习与动手 |
| ---: | --- |
| 5h | 研究 `DraftOutbox` 的批准边界；测试未经批准不能进入本地 outbox |
| 4h | 加入结构化日志与错误分类，观察一次完整分诊路径 |
| 4h | 设计实际 GitHub 适配器的只读与写入接口，画出权限和重复提交风险 |
| 3h | 扩充评测集并写一页失败案例分析 |
| 4h | 更新简历、录屏并持续投递，练习 3 分钟介绍第二个项目 |

**不要把 `--approve` 描述成生产级审批系统。** 它只是本地演示。真正连接 GitHub 后，还需要身份验证、明确的批准记录、目标仓库检查、重复发布保护和审计日志。

完成标准：能演示“先生成草稿、后由人确认”的流程，并解释为什么模型不应直接拥有发布权限。
